# MG-RISK-002 — Risk kernel reference algorithm (semantics_version 2)

Status: PROPOSED (VS-02A, candidate for independent review). Date: 2026-10-25. Supersedes the evaluation mechanics of MG-RISK-001 v0.2 §5.4, §5.5, §7 and §8 for `semantics_version = 2`; everything else in MG-RISK-001 (states, priority, Kleene logic, rule list, scenario catalog) stays in force except where §6 below lists a changed expectation.
Implementation: `backend/mineguard/risk/kernel.py` (pure; no detector, tracker, framework, clock or I/O imports). Conformance vectors: `backend/tests/test_risk_kernel.py`.

**Provenance of this reconciliation (CONFIRMED limitation).** The original text of audit findings H-1..H-6 is not in the repository (only their status in MG-DECISIONS-001 AP-28 and MG-RISK-001). The six contradictions below are the ones the builder found by reading MG-RISK-001/MG-DATA-001 against the needs of a live (webcam) source; they are labelled H-1..H-6 here for traceability and MAY differ from the original audit list. An independent review of this document is required (Codex cycle 1) and the owner should confirm the mapping.

## 1. Contradictions found and how version 2 resolves them
| ID | Contradiction in v0.2 | Version 2 rule |
|---|---|---|
| H-1 | §5.4 bridges an unknown run to T only when bracketed on BOTH sides, which needs look-ahead; §8.1 is a frame-by-frame machine and a live source has no future. | The kernel is **causal**: the value at sample `t` depends on samples `<= t` only. A dwell run survives an unknown run only if the run is bridgeable and the return to T happens within the tolerance (decided when the return arrives). Offline and streaming evaluation are identical (tested). |
| H-2 | §8.1 closes an ACTIVE episode "immediately" at the first frame of an "unbridged hole", which again needs look-ahead and contradicts the CLOSING/absorb rules used for every other unknown (S-28a vs S-22). | No special case. A hole is an unknown (`U`) sustain value: the episode enters CLOSING, is absorbed if known T returns within `close_hold`, else closes `inputs_unknown` with the cause list. (S-22 expectation changes, §6.) |
| H-3 | §5.4 applies bridging "before any rule logic", so a bridged T could satisfy an OPEN hold, while §8.1 says opening needs continuous T and no absorption before confirmation. | Bridging applies **only to dwell runs**. `HOLD(NV)` and candidate confirmation require continuous determinate T; any `F` or `U` resets them. Unknown never counts toward confirmation (S-43). |
| H-4 | Sustain was `DWELL ∧ NV`: after a non-bridgeable unknown (e.g. one `adapter_error` frame) the dwell restarts, so sustain becomes F and the episode could not be "absorbed" as S-28a states. | Dwell is needed to **open** a YELLOW episode only. Sustain is `TrackOcc ∧ NV` (person still determinately inside, no vehicle). Identity discontinuity is a separate, explicit flag (H-5). |
| H-5 | Identity: `identity_breaks` were producer-declared, but a real tracker cannot declare them; reappearance, ID switch and tentative tracks were unspecified. | A track id denotes one identity only while it is observed or absent within `track_gap_tolerance`. A discontinuity flag is raised by: a producer identity break; termination; a dwell run lost to an unbridgeable gap followed by a return (a NEW identity run); a dropped track. A discontinuity forces sustain F for that track at that sample and an episode in CLOSING cannot be absorbed after it (closes `track_discontinuity`). A tracker must emit `track_ref = null` for tentative tracks; an untracked person inside a zone makes R2 UNKNOWN (`identity_unavailable`), never YELLOW. Duplicate detections are not merged (documented limitation). |
| H-6 | Time: the catalog assumed a constant-rate, stride-1 file; a webcam delivers sparse, variable-rate samples, and a silence between samples was undefined. | `Params.max_sample_gap_us` (default 100 ms; about 2.5 sample periods for a sampled source). A silence longer than that inserts ONE pseudo-sample with cause `source_gap` at `prev + max_sample_gap_us`; the interval after it is UNKNOWN until the next sample. All holds and dwells are `>=` comparisons of event-time differences in integer microseconds. **Clock continuity (cycle-1 review MG-RISK-010):** a clock (open hold, `HOLD(NV)`, dwell) advances across two consecutive samples only if their spacing is `<=` that clock's own duration; otherwise it restarts at the later sample (candidate recorded as suppressed `sample_spacing_exceeds_hold`). A source sampled slower than a hold can therefore never confirm it, whatever `max_sample_gap_us` is. |

## 2. Inputs (per zone, per sample) — `Sample`
`t_us` (strictly increasing), `index`, `status ∈ {analyzed, not_analyzed, source_gap, adapter_error}`; for analyzed samples: tracked person items `{track_id: (V, cause)}`, `untracked_person`, `person_other` (ambiguous objects that may be persons), class-level `vehicle`, `terminated` tracks, `identity_breaks`, and `notes` (unknown causes to keep visible even when no value changes). V ∈ {T, F, U}; cause is one of the closed list of MG-RISK-001 §5.1. Zone Evaluation (not the kernel) produces these from observations; **the kernel never sees pixels, detector labels or confidences**.

## 3. Reference algorithm (one `ZoneEngine` per zone; per sample in order)
1. If the gap to the previous sample exceeds `max_sample_gap_us`, process a pseudo-sample (`source_gap`) first.
2. Per track: value `(v, cause)`: not analyzed → `U(hole cause)`; terminated → F (discontinuity); present → given value; absent: last value F → F, otherwise `U(track_absent)` until `track_unknown_hold` since last seen, then the item is dropped and recorded in `dropped_tracks`.
3. Dwell run per track (restarts if two consecutive samples are further apart than `dwell_us`): `T` starts or continues the run (a return after unknown continues it only if all causes were bridgeable and `t - last_T <= tol`, `tol = track_gap_tolerance` if `track_absent` among causes else `gap_tolerance`; otherwise a new run with discontinuity); `F` ends it; `U` keeps it pending and ends it as soon as the cause is not bridgeable or `tol` is exceeded. `DWELL = T` iff the track is T now and `t - run_start >= dwell_us`; U when the track is U; else F. `adapter_error` restarts the dwell but is not an identity discontinuity.
4. Class occupancy: person = Kleene OR of all person items (tracked, untracked, ambiguous); vehicle as given. A non-analyzed sample makes both U. `NV = ¬vehicle`; `HOLD = T` iff NV has been T continuously for `>= debounce_us` (restarts on F or U), U if NV is U, else F.
5. Instances: R1 (RED): open = sustain = `person ∧ vehicle`, `open_hold = close_hold = debounce`. R2 (YELLOW) per tracked person: open = `DWELL ∧ HOLD`, sustain = `TrackOcc ∧ NV`, `open_hold = 0`, `close_hold = debounce`. Untracked person item T/U, or an ambiguous object that may be a person (`person_other` T/U), → pseudo-instance R2 `U` (`identity_unavailable` or the ambiguity cause), so a possible person is never complete GREEN (cycle-1 review MG-RISK-011).
6. Episode machine per instance: INACTIVE→(open=T)→CAND (or ACTIVE if `open_hold=0`); CAND→ACTIVE when open stays T for `>= open_hold`, dropped to INACTIVE and recorded as a **suppressed candidate** on any F or U; ACTIVE→CLOSING on sustain ≠ T; CLOSING→ACTIVE (recording `absorbed`) if sustain is T again at a sample with `t - closing_start < close_hold` and no discontinuity occurred; at the first sample with `t - closing_start >= close_hold` the episode CLOSES even if sustain is T again at that very sample (uniform rule: every threshold is `>=` and takes effect at the sample where it is met; cycle-2 review MG-RISK-012), and if the condition is true at that sample a NEW candidate starts there. Closing reason, first match: `track_discontinuity`, `inputs_unknown` (causes listed), `rule_cleared`. End of stream: `end_of_stream` (right-censored; a CLOSING episode keeps `condition_until`; a CAND is recorded as suppressed).
7. State per sample: any live R1 episode → RED; else any live R2 → YELLOW; else UNKNOWN if the sample is not analyzed or any instance has open = U; else GREEN. GREEN carries `pending` when a candidate or an in-progress dwell/vehicle hold exists, so a pending condition is never displayed as "confirmed safe". Incomplete inputs (unknown causes of any instance, plus `notes`) are recorded on every live episode as one half-open range `[from_us, to_us)` per CONTIGUOUS run of samples carrying a cause (`from_index`/`to_index` = first/last such sample); a cause that disappears closes its range at the first sample without it and a returning cause opens a new range; open ranges close at the episode end (cycle-4 review MG-RISK-013).
8. Timeline: half-open intervals `[start, end)` covering `[0, end_us)` without gaps (an unobserved prefix before the first sample, and a stream with no sample at all, are UNKNOWN with cause `frame_not_analyzed`; cycle-2 review MG-RISK-013), split whenever state, active event ids, pending flag or cause set change; coverage per state partitions `total_us`.

## 4. Event and identity statements the UI may make
Only: "person in zone for ≥ dwell with no vehicle" (YELLOW) and "person and vehicle in the same zone for ≥ debounce" (RED), in image space, from an uncalibrated experimental detector; never distance, speed, collision, or that an accident occurred. A track id is an **IoU trajectory** (boxes that keep overlapping across consecutive samples), not a verified person: the tracker has no appearance evidence, ends the tracks involved when an association is ambiguous (crossing, merge, split), but cannot detect that one person replaces another in the same place between two samples, so per-person dwell may be overstated in that case (UI limitation `mg.lim.tracker_identity_not_guaranteed`). Across gaps the kernel understates, never overstates.

## 5. Determinism
Same samples, parameters and `end_us` ⇒ identical result dictionaries (compared structurally in tests, canonical-JSON serializable). The kernel contains no `datetime`, `time`, `random` or file access.

## 6. Differences from MG-RISK-001 catalog expectations
- S-22: YELLOW `[75,95)` closes `inputs_unknown` (`source_gap`), UNKNOWN `[95,120)`, GREEN `[120,165)`, YELLOW from 165 (v0.2: closed `unbridged_gap` at 80).
- S-19(b): the closing run of exactly 15 frames reaches `close_hold` at frame 115, so YELLOW closes there (`rule_cleared`) and must re-earn its vehicle-free hold (reopens at 130); the catalog said "YELLOW absorbs". Absorption now applies only strictly before the hold boundary.
- S-28a/b hold unchanged (a single adapter_error frame is absorbed; 20 frames close at 115 and restart dwell), reached through H-4 instead of the contradictory v0.2 sustain.
- All other P0 catalog vectors implemented in `test_risk_kernel.py` match the catalog. Not implemented here: refusal scenarios S-31..S-34, S-48..S-57 (they belong to the observation/policy validators of MG-DATA-001 and run on the existing validators), S-44/S-08 multi-zone independence (zones are independent `ZoneEngine` instances, covered in the integration tests), confidence-threshold scenarios S-30/S-59 (Zone Evaluation).

## 7. Limitations (unchanged)
Footpoint approximates ground contact; no de-duplication of overlapping detections; thresholds are experimental, not safety limits; a detector miss is GREEN; boxes are not calibrated positions.

## 8. Event identity and evidence (cycle-3 review)
- Event id = `evt_` + first 16 hex of SHA-256 over the canonical JSON array `["mg.event.id.v2", input_digest, zone_digest, zone_id, rule_id, rule_version, epoch, key, start_index]`. `input_digest` is the FULL canonical input of the evaluation: source and frame-table digests, observation-set digest, the complete policy (rule parameters, engine and semantics versions, tracker and its parameters), the stream end and the origin; `zone_digest` covers the exact canonical zone geometry. Any change of any of them changes every event id (cycle-4 review MG-EVENT-013). Ids shown by a LIVE webcam session are provisional (their context is `live-<session>`); the ids in the stored evaluation are final.
- Evidence references (file names and SHA-256 of encoded images) are outside the evaluation contract: they live in `evaluation.evidence_refs[event_id]`, are excluded from `evaluation.digest`, and are recomputed from the manifest at verification.
- A risk response/export is built from ONE zone-set snapshot: the evaluation and the returned zones are the same revision.

## 9. Conformance corrections of the night sprint (cycles 17-18) — UNREVIEWED
Two deviations of the implementation from this document were found and corrected, and the implementation version was bumped to `mg-risk-kernel/2.0.1` (`semantics_version` stays 2: the normative semantics above did not change): (a) the dwell clock restart for samples further apart than `dwell_us` (§1 H-6) now also applies when an unknown run is pending (a bridge across such a spacing is a new run and an identity discontinuity), and `dwell_us >= 1` is enforced; (b) a candidate whose dwell is satisfied while the vehicle-free hold is still accumulating is reported as `pending` instead of plain GREEN. The IoU tracker was `0.2.0` when this section was written (ambiguous associations end the tracks involved); the CURRENT tracker version is `0.3.0` (`backend/mineguard/risk/tracker.py`, `TRACKER_VERSION`). Artifacts stored by `2.0.0` / tracker `0.1.0` keep verifying: verification reports `risk_evaluation_engine_version_differs_from_current_not_compared` for their cached evaluation (the risk views always recompute from the observations with the current engine, so a different implementation legitimately yields different digests and event ids).

## 10. Silence closure (cycle-28 review MG-RISK-028, cycle-29 review MG-RISK-029; implementation `mg-risk-kernel/2.0.3`) — UNREVIEWED
Status of this section: PROPOSED; the independent review of the correction is pending. `semantics_version` stays 2. Sections 1 H-6 (the interval after the `source_gap` pseudo-sample is UNKNOWN) and 3 steps 6-7 (a CLOSING episode is live and shown by its colour until it closes) leave the closing time of an episode that crosses a silence open. Version 2.0.1 tested the close hold only at the next real sample, so an episode could extend over time in which nothing was observed (example: person and vehicle sampled every 100 ms up to 500 000 µs, next sample at 3 000 000 µs; the 500 ms hold had expired at 1 100 000 µs, but the event closed at 3 000 000 µs and the timeline stayed RED).
Rule as implemented: when the gap pseudo-sample puts an episode in CLOSING and `closing_start + close_hold` falls strictly before the next real sample, the episode closes AT that boundary with the usual closing reason (`inputs_unknown`, cause `source_gap`; `condition_until` = `closing_start`), and the timeline is UNKNOWN (`source_gap`) from the boundary to the next sample. No sample is fabricated, no later observation decides the closure, and the dwell and vehicle-free hold clocks are not touched. A real sample at exactly the boundary closes it by the uniform `>=` rule of step 6 (as before); a sample strictly before the boundary may still absorb it (as before). `finish(end_us)` applies the same rule to a trailing silence, WHATEVER the episode state (cycle-29 review MG-RISK-029): if the stream ends more than `max_sample_gap_us` after the last sample, the gap pseudo-sample is inserted and the rest of the stream is UNKNOWN (`source_gap`); an open episode follows the rule above (`end_us` before the boundary: right-censored `end_of_stream`; at or after it: closed by the rule) and a pending candidate is dropped as for any unknown. Version 2.0.2 applied this only when an episode was live, and the golden vector `test_unobserved_prefix_is_unknown_not_absent` expected a GREEN tail after a single sample; both contradicted H-6 and were corrected in 2.0.3 (the vector now expects UNKNOWN after the 100 ms covered by the last sample). Owner note: this changes the stored timeline of every evaluation whose stream ends more than `max_sample_gap_us` after its last sample (a different engine version, hence different digests and event ids). A stream whose end lies within `max_sample_gap_us` of the last sample is unchanged. Live display of a stalled source is governed separately by the observation freshness limit (`STALE_OBSERVATION_S`), which shows UNKNOWN; the stored event of a still-running feed is closed when the feed finishes. Conformance vectors: `backend/tests/test_risk_gap_closure.py`.
